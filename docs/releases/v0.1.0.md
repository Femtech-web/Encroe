**The studio shut down. The game didn't.** A studio seals its game server into a NEAR contract with no keys. While the
studio lives, anyone can check the sealed build is real without opening it; if the studio goes silent, anyone can
release it, and the game goes to its players with everything they earned. Built at NEAR HACKATHON.

## What is in v0.1.0

- **A game escrow nobody holds a key to.** `contracts/encroe-escrow`: a studio commits sealed epochs (its server
  core and every player's items, encrypted to a key NEAR's MPC network derives for the contract's identity) and sends
  heartbeats. If it goes silent past its grace period, anyone may call `release`, and the MPC network publishes the
  key. Every escrow is locked before anything is sealed: 0 access keys.
- **Verified without opening it, by hardware NEAR checks.** An Intel TDX enclave (OutLayer) runs the pinned verifier
  on the sealed package: every sampled player served exactly as committed, items conserved across seeded trades. The
  contract accepts a run only after **NEAR's own DCAP verifier** accepts its quote, bound to that run. A broken
  build turns the badge red ([life-52e4](https://github.com/Femtech-web/Encroe/blob/main/docs/results/escrow/life-52e4/README.md)).
- **A game to play, with its server in escrow.** Embergate (Rust): every move signed by a key the player's browser
  makes, every rule in the one wasm core the studio seals. The site's public world is sealed into
  `encroe-embergate.testnet` every six hours by a scheduled workflow, verified green.
- **"Is my stuff in the vault?"** Each player checks their own items against the root NEAR holds, from their
  browser, without revealing anyone else's (salted leaves; a player's proof only for a request signed by their key).
- **Kill a studio, bring the game back, play on.** On the site, a visitor releases a silent studio's escrow with one
  click (a real transaction; [kill-beaa](https://github.com/Femtech-web/Encroe/blob/main/docs/results/escrow/kill-beaa/README.md)),
  and the browser rebuilds the game from NEAR and FastFS alone: the release's signature, the package's hash, the
  decryption, the core, every player's items, a boot with zero imports. Then play goes on, with no server at all.
- **Any language.** Rust, C++ (Matchday, a football card club) and C (Neon City, an open-world city economy) game
  servers, sealed into their own escrows, verified green by the enclave, released and revived
  ([cores](https://github.com/Femtech-web/Encroe/blob/main/docs/results/escrow/cores/README.md)).
- **Try to break it, live.** Six real attacks on locked escrows from a stranger's account: early release, fake
  heartbeat, fake seal, tampered build, a replayed NEAR-accepted quote, a double release. Each refused on chain.
- **The preservation agent and an MCP server.** An agent that releases silent studios' games and brings every
  released game back with every check, every 30 minutes; the same tools for any AI over MCP.
- **For studios.** `/studios` (create an escrow from your wallet through the factory, keyless from birth), `/tools`
  (check your compiled core against the enclave's checks in your browser; check your players file; build recipes),
  `/escrows` (every escrow, read live from NEAR), and `scripts/studio/bot.sh` (seal, verify, heartbeat).

## Check it yourself

```bash
make test                     # 27 Rust tests: CKD vectors, IBE, the verifier, the escrow, the factory, the game core
cd web && npm ci && npm test  # 61 site tests: the browser's crypto against real released epochs, every core's checks
```

Any escrow's state, from any NEAR RPC: `status`, `get_state`, `get_runs`; its keys with `view_access_key_list`.

## Disclosed

- NEAR testnet only; no mainnet transaction was sent.
- In every recorded release we stopped the studio's heartbeat ourselves, the only way to show a studio disappearing
  on demand; sealed worlds hold players played by hand and players scripted through the same signed moves.
- The factory (`encroe.testnet`) is built and tested, and deploys once testnet's faucet allows.
- One public-world epoch (2) is stranded and can never be verified: the scheduled run's key row failed to store on
  Linux; fixed, and recorded in [embergate](https://github.com/Femtech-web/Encroe/blob/main/docs/results/escrow/embergate/README.md).
